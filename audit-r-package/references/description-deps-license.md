# Checklist: Metadata, dependencies, and licensing

Read `DESCRIPTION`, `NAMESPACE`, `LICENSE*`, and any `LICENSE.note` in full. Cross-check declarations against actual usage in `R/`, `tests/`, and `vignettes/`.

## DESCRIPTION fields

- **Package name** follows the rules: letters/numbers/periods only, starts with a letter, no trailing period. Flag underscores/hyphens (invalid).
- **Title**: one line, Title Case, no trailing period, < ~65 chars, doesn't start with "A package for" / the package name. Software/package names in single quotes.
- **Description**: one paragraph of full sentences, acronyms/URLs/package names in single quotes, no bare "This package".
- **Version**: valid (`major.minor.patch`, dev suffix `.9000`). Released versions should have three components. Flag `1.0` style two-component release versions.
- **Authors@R**: uses `person()`, not legacy `Author`/`Maintainer` free-text. Exactly one `cre` (maintainer) with an email. A `cph` (copyright holder) is present, especially important for a first CRAN submission. Bundled foreign code has matching `cph`/`ctb` entries.
- **License**: present and machine-readable (see licensing section below).
- **Encoding: UTF-8** present.
- **URL / BugReports**: present and point at the real repo / issue tracker. Broken links are a `urlchecker` finding.
- **LazyData**: present only if there is a `data/` directory; flag `LazyData: true` with no `data/`.
- **VignetteBuilder** declared if vignettes exist.
- **Roxygen / RoxygenNote**: present if roxygen is used; a stale `RoxygenNote` vs installed roxygen2 is a Note.
- **SystemRequirements** declared if `src/` or external tools are needed.
- **Config/** custom fields (e.g. `Config/testthat/edition`, `Config/Needs/website`) used rather than inventing top-level fields.

## Dependencies

- Every package used in `R/` (via `::` or `@importFrom`) is in **Imports**. Undeclared usage is a Critical (R CMD check catches it).
- Packages used only in tests/vignettes/examples are in **Suggests**, not Imports.
- Nothing listed in DESCRIPTION is unused anywhere. Flag orphan dependencies.
- **Depends** is used only for an R version floor or a genuinely inseparable attach-time dependency; flag ordinary packages parked in Depends.
- **No meta-packages in Imports/Depends**: `tidyverse`, `devtools`. Depend on the specific packages instead. (tidyverse in Suggests for a vignette is fine.)
- Version constraints use `>=` minimums, never `==` or upper bounds. Minimums are justified (a feature genuinely needs them), not cargo-culted.
- Dependency footprint is reasonable for the audience. Note heavy recursive trees; note when a "free" tidyverse dep (rlang, cli, glue, withr, lifecycle) would be cheaper than a heavy one.
- `LinkingTo` present if C/C++ headers from another package are used.
- 20+ non-default Imports triggers a CRAN NOTE - flag if approaching.

## NAMESPACE

- **Generated by roxygen2, not hand-edited.** A hand-edited NAMESPACE (no `# Generated by roxygen2` header) is a Warning - it drifts from the code.
- Exports match intent: only user-facing functions are exported; internal helpers are not. Over-exporting is hard to walk back.
- `importFrom` directives correspond to real usage; the `::` vs `importFrom` choice is consistent with the package's stated style.
- S3 methods are registered (`S3method()` present) for every method defined. Unregistered methods are a common, subtle bug.
- `useDynLib` present if `src/` exists.

## Licensing

- License field is machine-readable and matches the actual `LICENSE`/`LICENSE.md` files. Mismatch is a Warning.
- Standard license used a standard way: `MIT + file LICENSE` needs a `LICENSE` file with the two template lines (year, copyright holder); `LICENSE.md` (full text) is `.Rbuildignore`d.
- A license is present at all - no license means "all rights reserved" and blocks CRAN. Critical if missing.
- Bundled third-party code: original copyright/license headers preserved, `cph` entries in Authors@R, and a `LICENSE.note` documenting each component if licenses are mixed. Check that bundled licenses are *compatible* (can add restrictions, can't remove them; GPL code can't live in an MIT package; Stack Overflow snippets are CC BY-SA).
- Data packages: consider whether `CC0` or `CC BY` is more appropriate than a code license.
